# Product Rules

実装に迷ったときのプロダクト判断基準です。技術配置は[Architecture](ARCHITECTURE.md)、作業手順は[Workflow](WORKFLOW.md)を参照してください。

## 中心思想

- **旅を作品にする。** データ管理より、旅を思い出し、物語として残す体験を優先します。
- スクラップブックは **My Travel Magazine** です。ユーザーは入力担当ではなく、自分の旅行雑誌を仕上げる編集者です。
- 自動生成で十分に鑑賞できる状態を作り、ユーザー編集は作品を自分らしく整えるために使います。

## スクラップブック編集室

- 完成版を見ながらページ単位で編集し、管理フォームの一覧へ戻しません。
- Draft変更は完成プレビューへ即時反映します。
- 正式な永続保存は「記録を更新」で行います。
- 保存前の変更、保存失敗時のDraft、破棄確認を明確に扱います。
- 作品を主役にし、編集UIは静かで控えめにします。

## 写真

- `trip`は通常旅行写真、`cover-only`は所有Scrapbookの表紙素材です。
- `cover-only`を通常ギャラリー、写真件数、本文候補、TimeMachineへ混ぜません。
- 完全一致写真がある場合は既存写真の再利用を主要操作にします。
- ユーザーが明示した場合は同じ写真の新規追加も許容します。
- 写真の`trip`／`cover-only`用途や所有先を自動変換しません。

## 安全性

- データ削除は安全側に判断し、参照検索失敗を「参照なし」と扱いません。
- 使用中データの自動解除・自動削除は、対象と復旧方法が明確なPhaseでのみ行います。
- 後方互換と端末内データの保持を、実装上の簡潔さより優先します。

## モバイルとアクセシビリティ

- モバイル優先で設計し、393pxを基準に430px、768px、1024pxへ展開します。
- 操作領域は44px以上を維持します。
- 選択・状態・エラーを色だけで伝えません。
- キーボード、Focus、Safe Area、`prefers-reduced-motion`を既存仕様に合わせます。
- 説明文を常設しすぎず、プレビューや主要操作の表示領域を圧迫しません。必要な説明は状態表示、Toast、Dialogなど適切な時点で提示します。
